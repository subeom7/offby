# 멀티플레이 방

방에 모인 사람들에게 **같은 정수 하나**가 주어지고 **동시에 시작**한다.
그 숫자에 가장 가까이 멈춘 사람이 그 라운드를 이긴다. 라운드마다 1점씩
쌓이는 다전제다.

관련 파일: `src/room.js`, `src/lib/room-logic.js`, `src/worker.js`

---

## 1. 동시 시작에 정밀한 시계 동기화는 필요 없다

여기가 이 기능의 핵심 통찰이고, 설계 전체를 단순하게 만든 지점이다.

각자의 오차는 **자기 기기의 `performance.now()` 차이**로 잰다. 서버 시각도,
남의 시각도 계산에 들어가지 않는다. 그래서 시계가 서로 어긋나 있어도
**점수의 공정성은 전혀 영향받지 않는다.**

동시 시작이 필요한 건 두 가지 때문이다.

- 다 같이 카운트다운을 보는 체감. ±50ms면 사람은 못 느낀다.
- 서버가 라운드 창을 알아야 부정 제출을 거를 수 있다.

그래서 시계 보정은 입장할 때 ping/pong 다섯 번으로 끝난다. 왕복이 가장
짧았던 샘플 하나만 쓴다 — 큐에 걸린 샘플은 편도 지연 추정이 크게 어긋난다.

```
offset = 서버시각 − (보낸시각 + 왕복/2)
내 시계의 시작 시각 = startAt − offset
```

라운드마다 다시 맞추지 않는다. 몇 분 사이의 드리프트는 3초 카운트다운에
아무 영향이 없다.

## 2. 프로토콜을 얇게 유지하는 이유

**WebSocket 메시지 하나가 Durable Object 요청 하나로 과금된다.** 무료
티어가 하루 10만이다. 위치를 실시간으로 흘려보내는 류의 설계는 여기서
바로 예산을 태운다.

| | DO 요청 |
|---|---|
| 입장 1인 (ping/pong 5쌍 + hello + welcome) | ~12 |
| 라운드 1회 1인 (round 수신 + stop 송신 + result 수신) | ~3 |
| 5인 방 라운드 1회 | ~15 |

하루 10만 → 5인 방 기준 수천 라운드. 라운드당 1인 3메시지를 넘기지 않는
게 설계 제약이다.

```
client → server   hello{id,name} · ping{c} · start · stop{roundId,elapsed} · bye
server → client   welcome · pong{c,s} · roster · round · submitted · result · error
```

## 3. 부정 제출: 도착창

`stop`이 서버에 닿은 시각을 본다.

```
drift = 도착시각 − (startAt + elapsed × 1000)
−150ms ≤ drift ≤ +2500ms
```

**음수 쪽이 좁은 게 핵심이다.** "3.000초를 쟀다"면서 시작 0.4초 만에
도착하는 메시지는 물리적으로 불가능하다 — 값을 지어낸 것이다. 양수 쪽은
느린 회선을 봐줘야 해서 넉넉히 둔다.

창을 벗어난 제출은 그 라운드 DNF다. 거절 메시지를 따로 보내지 않는다 —
어차피 결과표에 '기록 없음'으로 나온다.

방 성적은 **글로벌 리더보드에 반영하지 않는다.** 친구끼리 짜고 치는 방이
전체 순위를 밀어 올리는 경로를 원천 차단한다.

## 4. 방 하나 = Durable Object 하나

이름이 곧 방 코드다. 상태(로스터·점수·라운드)는 DO 저장소에 있어서
하이버네이션에서 깨어나도 이어진다.

- **WebSocket Hibernation API.** 방에 들어와 놓고 한참 아무것도 안 하는
  게 이 게임의 정상적인 모습이다. 그 동안 객체가 메모리에 떠 있을 이유가
  없다. 연결은 런타임이 들고 있고 메시지가 올 때만 깨어난다.
- **소켓에 신원을 붙여 둔다**(`serializeAttachment`). 깨어났을 때 이
  소켓이 누구인지 알아야 한다.
- **알람은 하나뿐**이라 라운드 마감과 방 정리를 같이 태운다. 둘 중 먼저
  올 시각에 맞춰 두고, 깨어나서 무엇이 걸렸는지 본다.

### 라운드가 끝나는 두 가지 경우

1. 전원이 냈을 때. 마감까지 붙잡고 있을 이유가 없다.
2. 마감(`startAt + 목표 + 6초`)에 알람이 깨워서. 안 낸 사람은 DNF.

**나간 사람을 기다리다 멈추면 안 된다.** 누가 나갈 때 남은 사람이 모두
냈으면 그 자리에서 라운드를 닫는다.

### 그 밖에

- 방 코드 4자, 알파벳은 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` — 0/O, 1/I를
  뺐다. 목소리로 불러 주는 값이다.
- 코드 발급은 DO에 `claim`을 물어본다. 사람이 아직 안 들어온 방이라도
  방금 발급된 코드(2분)는 다시 내주지 않는다.
- 방장은 첫 입장자. 나가면 남은 사람 중 가장 먼저 들어온 사람이 이어받는다.
- 새로고침하고 돌아오면 자리와 점수를 그대로 이어받는다(신원이 기기 ID라서).
- 정원 8명. 마지막 활동 후 30분이면 방을 지운다.
- `/r/ABCD`에는 `X-Robots-Tag: noindex`가 붙는다. 방 코드가 검색에 걸리면
  모르는 사람이 남의 방에 들어온다.

## 5. 테스트

`wrangler dev`는 Node 22를 요구하는데 CI와 로컬은 20이다. 그래서
`cloudflare:workers`를 대역으로 돌려(`test/stub/`) **워커 런타임 없이**
Room을 노드에서 그대로 돌린다.

여기서 깨지기 쉬운 건 런타임 바인딩이 아니라 **순서**다 — 누가 방장인가,
나간 사람을 기다리다 멈추지 않는가, 마감에 안 낸 사람이 DNF가 되는가.
ctx와 소켓을 대역으로 두면 그 순서를 시간까지 통제하면서 볼 수 있다.

```
npm run test:room     # 방 상태 전이 53개
npm run test:client   # 방 화면 (WebSocket 대역)
```
