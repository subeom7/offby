# 리더보드

만들었다. 이 문서는 **왜 이렇게 됐는지**를 남긴다. 붙이기 전에 적어 둔
계획에서 한 군데가 실제로 뒤집혔는데, 그 부분이 제일 읽을 값어치가 있다.

관련 파일: `src/worker.js`, `src/lib/{run,board,sign,ids}.js`, `src/schema.sql`

---

## 1. 순위 기준: 연속 10회의 평균

단발 최고 기록은 **운으로 0.001s가 나온다.** 상위권이 전부 0.000~0.003s로
몰려서 변별력이 사라지고, 부정에도 가장 약하다 — 한 번만 운 좋게(또는
한 번만 조작해서) 찍으면 끝이다.

연속 10회 평균은 그 두 문제를 같이 푼다. 운이 평균에 묻히고, 조작하려면
열 번을 다 조작해야 하며, 게임을 더 오래 붙잡는다.

**목표가 정수 2~9로 고정된 게 여기서 결정적이다.** 종류가 8개뿐이라 서로
다른 사람의 런을 비교할 수 있다. 소수점 목표였다면 난이도가 제각각이라
순위 자체가 성립하지 않는다.

일간(UTC 자정 리셋)과 전체 기간 두 보드를 둔다. 전체만 있으면 몇 주 뒤
상위권이 고착돼 새로 온 사람에게 "이길 수 없는 표"가 된다.

## 2. 뒤집힌 것: 목표를 미리 준다

계획은 **매 시도마다 서버가 목표를 발급**하는 구조였다. 실제로 만들면서
바꿨다. 이유가 셋인데 마지막이 결정적이다.

1. 시도마다 왕복이 생겨 650ms 락아웃 안에 네트워크가 끼어든다. 느린
   회선에서 게임이 눈에 띄게 끊긴다.
2. 런당 요청이 11개 → 2개로 준다. 무료 티어가 하루 10만이다.
3. **막아 주는 게 사실상 없다.** 목표는 어차피 매 시도 *전에* 화면에
   띄워 준다 — 그게 게임이다. 봇은 지금도 목표를 안다. 미리 주든 그때
   주든 봇 입장에서는 똑같다.

그래서 목표 10개를 한 번에 뽑아 **HMAC으로 서명해서** 내려준다. 서명이
목표 배열까지 덮으므로 쉬운 목표로 바꿔치기하면 제출 때 걸린다.

```
POST /api/run/start   → { runId, targets:[10], issuedAt, token }
POST /api/run/finish    { runId, targets, issuedAt, token, attempts:[10], playerId, nickname }
```

## 3. 실제로 막는 것

### 벽시계 하한

```
제출시각 − 발급시각  ≥  Σ elapsed + 락아웃 × 9
```

55초짜리 런을 3초 만에 제출할 수는 없다. 발급 시각은 서버가 찍고
네트워크 지연만큼 클라이언트보다 앞서 있으므로, 이 하한은 실제 플레이보다
**항상 느슨하다** — 정직한 런이 여기 걸리지 않는다.

상한은 두지 않는다. 런 도중에 자리를 비우는 건 부정이 아니다. 토큰
수명(30분)으로만 자른다.

### 사람의 한계

평균오차가 `HUMAN_FLOOR`(0.008s) 아래면 플래그. **이 숫자에는 아직 근거가
없다.** 실측 분포를 모으기 전이라 어떤 값을 박아도 임의적이다.

그래서 걸린 런을 **버리지 않는다.** `flagged=1`로 저장해 두고 순위에서만
뺀다. 나중에 분포를 보고 임계값을 정할 때 데이터가 남아 있어야 한다.

### 나머지

- `run_id`가 PRIMARY KEY다. 같은 런을 두 번 제출하면 DB가 막는다.
- 플레이어당 시간당 30런 레이트리밋.
- 순위에는 **플레이어별 최고 런 하나씩만** 올린다. 잘 나온 런을 여러 개
  올려 상위권을 도배할 수 없다.

여기까지 해도 정직하게 라운드를 열고 자동화로 정확히 누르는 경우는 남는다.
클라이언트가 시간을 재는 게임에서 그건 원리적으로 못 막는다. 목표는
완벽한 차단이 아니라 **가벼운 부정을 귀찮게 만드는 것**이다.

## 4. 신원: 로그인 없음

틱톡에서 유입되는 게임에서 로그인 화면은 이탈 지점이다. 첫 방문에
`crypto.randomUUID()`로 기기 ID를 만들어 `localStorage`에 넣고, 이름만
받는다. 서버에는 그 UUID를 **비밀키로 한 번 더 해시한 값**만 저장한다 —
저장본이 새도 다른 서비스의 식별자와 이어 붙일 수 없다.

이름은 열 번을 다 친 **뒤에** 받는다. 먼저 받으면 그 자리가 이탈
지점이 되는데, 거기까지 온 사람은 이미 게임을 한 판 끝낸 사람이다.

**IP를 신원으로 쓰지 않는다.** 모바일 캐리어 NAT 뒤에서는 수만 명이 같은
IP를 쓰고, IPv6는 프라이버시 확장으로 주소가 계속 바뀌며, 무엇보다 IP는
개인정보라 저장하면 처리 근거와 보관기간이 따라붙는다. 순위표 하나
만들려고 질 부담이 아니다.

## 5. 저장소

**Cloudflare D1**(엣지 SQLite). 스키마는 `src/schema.sql`.

순위표는 `caches.default`에 30초 캐시한다. D1을 매 요청 때리면 무료
티어(하루 500만 행)를 금방 쓴다. 30초 늦게 갱신되는 걸 신경 쓰는 사람은
없다.

보관은 30일이되 **플레이어별 최고 런은 남긴다.** 그냥 오래된 걸 다 지우면
'전체 기간' 보드가 조용히 '최근 30일' 보드가 된다. 하루 한 번 cron이
정리한다.

## 6. 남은 것

- `HUMAN_FLOOR`를 실측으로 다시 정하기. `flagged` 행이 그 재료다.
- 닉네임 중복. 지금은 허용한다. 사칭이 문제가 되면 그때 생각한다.
- 욕설 필터. 지금은 길이·제어문자·방향 전환 문자만 턴다(`src/lib/ids.js`).
